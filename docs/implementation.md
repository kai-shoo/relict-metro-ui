## End-to-end examples

- The top navigation stays in sync with Frame. It expands in a narrow container and passes Back to the application. A transfer moves the selected items from several lists to a target group. Keyboard, mouse, and Cross-slide use the same transaction. Tests include touch emulation through CDP. [Projects](../examples/navigation/) · [Collections](../examples/collections/)
- The radio archive opens the destination once after the user signs in. It supports cancellation and uses the same player for search results and recent records. A replaceable local adapter demonstrates the authentication contract. [Shell launch](flows.md#27-shell-activation-and-a-shared-player) · [Radio archive](../examples/music/)
- The drafts example saves versions and submits them over HTTP with an idempotency key. It checks receipts after a reload. It opens offline after the first visit. The demo server keeps receipts in process memory. The open page submits drafts. [Contract of dispatch](../examples/drafts/README.md)
- Clipboard commands check the document, text, and selection before they apply the command. Field sheets store ink strokes by page. The annotation list restores focus and position. Browser tests cover ClipboardEvent, the clipboard adapter, and pen emulation. [Exchange buffer](../examples/clipboard/) · [Annotations](../examples/annotations/)
- The Share target service worker parsed a real multipart request in Chromium. The preview and destination selection use IndexedDB. A supplied `launchQueue` callback tests file activation. Installation and activation from the system menu still need a shell integration test. [Import](../examples/imports/)

Each addition from the selection creates a queue entry with a unique key. Before the example adds items, it checks availability through HTTP and reports the names of items that it skips. Back returns focus to the selection button. [Compilation](../examples/collections/selection.html)

The catalog maps all 119 registered tags to an import, HTML markup, and a working example. A test compares the list with the npm package exports. [Catalogue](../examples/catalog/) · [API Handbook](api.md)

The browser engine tests ran on Linux. For the form, Chromium exposed the accessible name, external description, error, and status change through AT-SPI. Orca 51.1 produced speech for the field and the save confirmation. In the request list, the result count changed once. Two subsequent responses did not change the count. Orca made one announcement. The check used the speech output text. These tests do not cover a physical camera, a physical pen, the system Back gesture, the installed shell, or Safari on physical devices.

The example tests use axe-core 4.14.1 to check accessible names and contrast. In the catalog, the automated name check accounts for text in an expanded tree item's children and changing LiveTile face content. Chromium's accessibility tree gives the parent and child separate names. Tile links keep a stable destination name and report count updates through a separate status.
