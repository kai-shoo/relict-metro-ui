## Навигационные поверхности

| Поверхность | Когда применять | Содержимое и связь с остальным экраном |
| --- | --- | --- |
| **Frame / Page** | У пользователя есть отдельные места назначения и история посещений. | Frame управляет маршрутом и журналом. Page задаёт заголовок, область содержимого, команды и политику закрытия. Переход к другому объекту может создать запись истории. |
| **Panorama** (Phone 7–8 Silverlight) | Главная обзорная поверхность с несколькими разнородными областями. | Один широкий холст. Фон, общий заголовок, заголовки секций и содержимое двигаются слоями. Превью, строки и ссылки ведут в детали или специализированные страницы. |
| **Phone Hub** (8.1 Phone Store) | Обзор приложения и вход в связанные области. | Hub, HubSection, необязательные заголовки, собственное содержимое секций. Microsoft описывает portrait, цикл при трёх и более секциях, максимум пять секций, возврат в последнюю секцию и минимизированную панель. |
| **Desktop Hub** (Windows 8.1 Store) | Обзор большой коллекции с разными способами входа. | Секции образуют навигацию верхнего уровня. Заголовок секции может открыть отдельную страницу. |
| **Pivot / PivotItem** | Равноправные представления одного контекста, например фильтры входящих. | Заголовки переключают панели. | **SelectorBar** (WinUI) | Несколько небольших, однозначных переключателей представления. | Видимый выбор меняется на месте. Приложение привязывает выбранный пункт к представлению. |

### Hub для Windows Store 8.1

У настольного Hub есть общий заголовок, секции со своими данными и необязательный акцентный блок hero. Интерактивный заголовок секции показывает шеврон и поднимает событие перехода. Для просмотра всего раздела приложение открывает отдельную страницу. При запуске Hub сначала подготавливает видимые секции, остальное загружает позже. В узком режиме секции можно расположить вертикально. Приложение сохраняет позицию прокрутки, а Semantic Zoom может открыть обзор секций. [Описание Hub от команды Windows](https://blogs.windows.com/windowsdeveloper/2014/02/05/introducing-the-new-hub-control-for-heterogeneous-data/)

| Часть | Ответственность в библиотеке |
| --- | --- |
| Общий заголовок и hero | Называют контекст и показывают приоритетную подборку. Интерактивные элементы hero публикуют свои команды и назначения. |
| Обычный заголовок секции | Даёт имя области для чтения, фокуса и навигации по секциям. |
| Интерактивный заголовок | Имеет доступное действие открытия всего раздела. Переход передаёт ключ секции, местоположение и источник фокуса. |
| Тело секции | Управляет запросом данных, отображением и локальными действиями. Ошибка в секции имеет свой статус и повтор. |
| Обзор секций | Разрешает один и тот же ключ при переходе из общего обзора к конкретной секции. Детальные страницы используют журнал Frame. |

### Поверхности Windows Phone 8.1 XAML и WinJS

Числа из XAML-шаблонов и ранних исходников WinJS приведены с привязкой к версии и источнику. [Визуальные спецификации Phone 8.1 Store apps](store-81-visual-specs.md)

В Windows Phone 8.1 команда Visual Studio сопоставляла Panorama из Silverlight с Hub из Windows Runtime XAML. Для Phone XAML также были Pivot, WebView и ContentDialog. В настольном Windows Store 8.1 из этого набора присутствовали Hub и WebView. Проекты могли совместно использовать данные и контекст перехода, а представление выбиралось по профилю. Образец Microsoft разделяет элемент заголовка с экранной кнопкой Back для Windows и обработку аппаратного Back для Phone. [Шаблоны и таблица контролов XAML](https://devblogs.microsoft.com/visualstudio/authoring-windows-8-1-apps-in-xaml/) · [Совместные страницы и контролы](https://blogs.windows.com/windowsdeveloper/2014/07/22/tips-and-tricks-for-using-xaml-controls-in-your-universal-windows-apps/)

У Phone Hub в XAML горизонтальная раскладка, секция по умолчанию занимает 90% ширины окна, а две секции не образуют цикл. API передаёт список видимых секций через `SectionsInViewChanged`. В примере Microsoft AppBar показывал основную команду и включал компактный режим, пока секция недавних элементов шла первой в этом списке. При уходе с неё панель возвращалась в минимальный режим. [Правила Phone Hub](https://blogs.windows.com/windowsdeveloper/2014/07/22/tips-and-tricks-for-using-xaml-controls-in-your-universal-windows-apps/) · [Сценарий Hub и панели команд](flows.md#25-phone-hub-и-команды-текущей-секции)

Гайд Phone Hub описывает общий заголовок, фон, заголовки секций и содержимое как независимо движущиеся слои. Общий заголовок должен сохранять читаемость на всех участках фона. Контрол, которому нужен собственный горизонтальный жест, открывается на отдельной странице. Например, карточка с превью карты открывает интерактивную карту, а Back возвращает к той же секции Hub. [Оригинальные рекомендации Phone Hub](https://web.archive.org/web/20140408233046id_/http://msdn.microsoft.com/en-us/library/windowsphone/design/dn596112.aspx) · [Сценарий конфликта жестов](flows.md#10-свайп-прокрутка-и-конфликт-осей)

WinJS 2.1 добавил Pivot для Phone, где он мог содержать ListView. Перечень контролов в этой ветке отличается от XAML. Flyout, Menu, NavBar, SearchBox, SettingsFlyout, Tooltip и BackButton отсутствуют в Phone WinJS 2.1. При описании поддержки компонентов библиотека указывает вариант платформы. [WinJS on Windows Phone 8.1](https://blogs.windows.com/windowsdeveloper/2014/04/18/winjs-on-windows-phone-8-1/)

В руководстве по миграции Silverlight на Windows Runtime 8 Microsoft сопоставляет PhoneApplicationFrame и NavigationService с Frame, PhoneApplicationPage с Page, Panorama с Hub, LongListSelector с SemanticZoom и ApplicationBar с CommandBar. Иконки Silverlight App Bar соответствуют `PrimaryCommands`, пункты раскрываемого меню — `SecondaryCommands`. При переносе поведение конкретного элемента определяется его профилем. [Таблица сопоставления классов](https://learn.microsoft.com/en-us/previous-versions/windows/apps/dn800286(v=win.10))

В руководстве Phone 8.1 по Pivot горизонтальные жесты зарезервированы за переключением панелей. Вертикальные списки и ссылки остаются интерактивными. Независимые задачи с текстовым вводом, картой или другим горизонтальным жестом выводятся на отдельную страницу. Объект в панели может открыть такую страницу через Frame. [Оригинальные рекомендации Pivot](https://web.archive.org/web/20140413025235id_/http://msdn.microsoft.com:80/en-us/library/windowsphone/design/dn596104.aspx) · [Конфликт жестов](flows.md#10-свайп-прокрутка-и-конфликт-осей)

### Контракт библиотеки для страниц и секций

В Phone 8.1 запись Frame соответствует месту, куда пользователь может вернуться. К таким местам относятся обзор Hub и страница деталей. Заставка, диалог входа и экран ошибки относятся к временным состояниям. Панель Pivot и смена объекта внутри одной карточки сохраняются в состоянии своей страницы. Back закрывает временный слой либо возвращает к предыдущей странице Frame. [Pages, screens и item enumeration в MSDN](https://web.archive.org/web/20140501211142id_/http://msdn.microsoft.com:80/en-us/library/windows/apps/dn596119.aspx)

- **Страница.** Входные данные — идентификатор маршрута, параметры, необязательный заголовок, содержимое, набор команд, правила возврата и восстановления фокуса. Сигналы — запрос перехода, успешное открытие, закрытие. Страница с формой может приостановить уход до подтверждения.
- **Panorama/Hub.** Входные данные — стабильные идентификаторы секций, заголовки, необязательный общий фон, стартовая секция и политика цикла. Состояния — ожидание ввода, drag, приведение к позиции, завершённая секция. Модель отличает видимый сдвиг от подтверждённого sectionId. Превью может запросить маршрут, сохранив секцию и якорь. Для исторического Phone Hub цикл включается с трёх секций. Для других профилей это явная настройка.
- **Pivot.** Входные данные — набор одноуровневых представлений с независимыми состояниями загрузки и прокрутки. Активация заголовка, клавиатурный выбор и завершённый свайп меняют `value` и отправляют одно событие `metro-change`. Присваивание через API обновляет интерфейс без события. Визуальные копии на границе цикла остаются вне порядка чтения и фокуса. Если текущий пункт удалён или отключён, Pivot выбирает первый доступный в порядке разметки. При пустом наборе `value` становится пустой строкой.
- **Связь Hub и Pivot.** Hub открывает маршрут с Pivot через ссылку или строку. В Phone 8.1 эти контейнеры размещаются на отдельных страницах. Карту, карусель или слайдер, которым нужна та же ось жеста, можно открыть в отдельном маршруте. В Phone 7 гайд отдельно описывает вертикально прокручиваемые секции Panorama и широкие горизонтальные секции. Для Phone Hub применяются собственные ограничения из главы 2014 года.
- **Современный профиль.** Текущая документация WinUI рекомендует для Windows 11 SelectorBar или NavigationView в сценариях, где прежде использовали Pivot. В Metro-профиле сохраняются соседние заголовки и перелистывание. Выбор между профилями задаёт интерактивную геометрию и модель переполнения. [Pivot в WinUI](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/pivot)

### Ограничения по версиям Windows Phone

### Документные вкладки TabView

В WinUI при входе в ряд вкладок фокус получает активная вкладка. Стрелки перемещают фокус по ряду, а Space или Enter активируют вкладку с фокусом. Ctrl+Tab и Ctrl+Shift+Tab циклически переключают вкладки вперёд и назад. Кнопка закрытия и Ctrl+F4 поднимают `TabCloseRequested`. При закрытии решение относится к черновику запрошенной вкладки. Закрытие фоновой вкладки сохраняет фокус и историю активной. ### Контракт библиотеки для команд

Одна команда предоставляет идентификатор, подпись, значок, условие доступности и операцию над определённой целью. Панель, переполнение, меню, видимая кнопка и комбинация клавиш получают одну актуальную модель. Состояние команды обновляется при изменении выбора или маршрута. На выполнение передаётся определённая цель, захваченная в момент вызова и проверенная перед изменением данных.

Открытый временный слой хранит триггер и предыдущее положение фокуса. Закрытие возвращает фокус к триггеру, а при его исчезновении — к устойчивому элементу области-источника. Подтверждение разрушительного действия завершает меню и открывает модальный шаг. Отмена оставляет данные и выбор. У операции со временем выполнения есть режим `pending`, понятный результат и защита от повторного запуска. Обратная связь встраивается туда, где её ожидает пользователь.

В руководстве Windows 8.1 Flyout открывается рядом с вызвавшим его контролом. Немедленное изменение переключателя в открытом Flyout применяет значение и сохраняет слой открытым. Команда с подтверждением, например «Сохранить», применяет подготовленное значение и закрывает слой. Нажатие снаружи или Escape позволяет закрыть слой без выполнения такой команды. [Guidelines for flyouts](https://web.archive.org/web/20140408235720id_/http://msdn.microsoft.com/en-us/library/windowsphone/design/hh465341.aspx)

В WinUI Flyout принимает фокус, пока открыт. Нажатие снаружи обычно закрывает слой и поглощает сам жест. `OverlayInputPassThroughElement` разрешает передать это же нажатие одному явно указанному элементу, например соседней кнопке меню. Для библиотеки закрытие слоя и активация нижнего элемента задаются отдельно. Диалог подтверждения завершает действие через свой результат. [Flyout](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/dialogs-and-flyouts/flyouts) · [ContentDialog](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/dialogs-and-flyouts/dialogs)

### Команды с клавиатуры

В WinUI объект команды может обслуживать кнопку, меню и сочетание клавиш. `CanExecute` определяет доступность одного действия для всех входов. `ScopeOwner` позволяет привязать сочетание к области, например к списку, которому принадлежит контекстное меню. Alt показывает подписи клавиш доступа в текущем меню или представлении. [Commanding in Windows apps](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/commanding) · [Keyboard accelerators](https://learn.microsoft.com/en-us/windows/apps/develop/input/keyboard-accelerators) · [Access keys](https://learn.microsoft.com/en-us/windows/apps/develop/input/access-keys)

В контракте библиотеки клавиатура и видимые кнопки передают одной команде текущий контекст. Контекст выбирается по фокусу, активному документу и верхнему слою. Перенос кнопки в overflow меняет её положение, а область действия команды задаётся владельцем. [Сценарий переключения контекста](flows.md#34-команды-с-клавиатуры-и-область-действия)

### AppBar Phone 8.1 WinJS

В закрытом состоянии `minimal` показывает многоточие, `compact` показывает до четырёх кнопок. Касание или перетаскивание многоточия раскрывает подписи и вторичные команды. `global` на телефоне означает первичные команды, `selection` уходит в раскрываемый список. В настольном WinJS эти группы раскладывались у противоположных краёв панели. При повороте телефона полоса оставалась у физического нижнего края корпуса, а текст и значки поворачивались. ### Размещение команд в Windows 8.1 Store apps

В настольной модели верхняя панель служит для переходов, а нижняя открывает команды текущей страницы или выбора. Команда, которая постоянно нужна для основной задачи, размещается рядом с содержимым. Пока есть выбор, панель может оставаться открытой в режиме sticky. Гайд просит при этом оставить доступной полосу горизонтальной прокрутки под содержимым. ### Модели взаимодействия коллекции в Windows 8.1

Руководство Windows Store описывает четыре профиля для одной семьи контролов. В WinJS список и сетка были компоновками `ListView`. В XAML это два отдельных контрола. Ниже поведение исторического профиля. [Guidelines for list and grid view controls](https://web.archive.org/web/20140413013343/http://msdn.microsoft.com/en-us/library/windowsphone/design/hh465465.aspx)

| Профиль | Что происходит при касании и выборе | Связанный компонент |
| --- | --- | --- |
| Каталог | Касание активирует объект. Поперечный жест может добавлять предмет к выбору. В WinJS это `invokeOnly` и `swipeBehavior: select`. | Детальная страница получает активированный объект, панель команд получает текущий выбор. |
| Список и детали | Касание выбирает строку и обновляет детали. В WinJS это `directSelect`. Для одиночного выбора поперечный выбор отключён. | Отдельная панель деталей читает выбранный ключ. |
| Пикер | Касание меняет выбор. В описанном профиле выбор также доступен поперечным жестом. | Поверхность выбора возвращает выбранные элементы вызывающему контексту. |
| Статическое содержимое | Строки читаются. Выбор и активация отключены. | Контейнер отображает данные без перехода к странице объекта. |

Для узкого окна и портретной ориентации гайд предлагает заменить горизонтальную WinJS-сетку вертикальным списком. Для длинного сгруппированного набора можно сначала показать группы, затем список группы с явным возвратом. WinJS сохраняет `indexOfFirstVisible` перед изменением размера. В библиотеке сохранение по ключу позволяет вернуться к той же записи и после перестановки данных. [Список и детали на узком и широком экране](flows.md#7-список-и-детали-на-узком-и-широком-экране) · [Сохранение фокуса](flows.md#30-обновление-коллекции-с-сохранением-фокуса)

У ScrollViewer в руководстве 8.1 область просмотра и одна или две полосы по размерам содержимого. Гайд рекомендует использовать встроенную прокрутку списка, поля или Hub, а самостоятельный ScrollViewer размещать вокруг одной области содержимого. В ней может быть панель с несколькими дочерними элементами. Для длинного текста используется вертикальная ось. Для полноразмерного изображения с масштабированием может потребоваться две оси. [Guidelines for scroll bars](https://web.archive.org/web/20140408235721/http://msdn.microsoft.com/en-us/library/windowsphone/design/dn439342.aspx) · [Конфликт осей](flows.md#10-свайп-прокрутка-и-конфликт-осей)

### Быстрый переход по группам

В листе Phone 8 механизм Quick Jump показан как слой над длинным списком. Его содержимое может быть алфавитом, именованными группами или датами. После выбора активируется исходный список на позиции выбранной группы. В библиотеке слой получает группы из актуальной коллекции, а переход передаёт стабильный ключ, который может разрешить виртуализированный список. [QuickJumpGrid в экранных шаблонах Phone 8](windows-phone-archive.md#состав-набора-windows-phone-8) · [LongListSelector SDK](https://learn.microsoft.com/en-us/previous-versions/windows/apps/jj208486(v=vs.105))

В Silverlight Phone 8 LongListSelector поддерживал виртуализированную компоновку списком и сеткой. JumpList имел собственную компоновку, поэтому сетка фотографий могла открывать обзор групп обычным списком. В XAML для Windows Phone 8.1 касание заголовка группы открывало обзор SemanticZoom, сохраняя жест Phone 8. На Windows 8.1 в примере Microsoft обзор открывался сведением пальцев. Доступность пунктов обзора вычисляется по текущим группам. [Windows Phone 8 XAML LongListSelector](https://blogs.windows.com/windowsdeveloper/2013/05/23/windows-phone-8-xaml-longlistselector/) · [SemanticZoom в универсальных приложениях 8.1](https://blogs.windows.com/windowsdeveloper/2014/07/22/tips-and-tricks-for-using-xaml-controls-in-your-universal-windows-apps/)

В гайде SemanticZoom обе поверхности используют один набор данных и согласованную ось прокрутки. Обзор может представлять категории, инициалы, даты или страницы. Рекомендовано до трёх экранов обзора, чтобы переход оставался быстрым. В Phone 8.1 касание заголовка открывает обзор, а выбор ключа возвращает детальную поверхность с соответствующей группой в области просмотра. [Guidelines for semantic zoom](https://web.archive.org/web/20140408235721/http://msdn.microsoft.com/en-us/library/windowsphone/design/hh465319.aspx)

### Cross-slide и подборка выбранного

В руководстве для Windows Store 8.1 cross-slide работает поперёк единственной оси прокрутки коллекции. Короткое движение за порогом с отпусканием меняет выбор. При продолжении движения за следующий порог начинается перенос. Tap может по-прежнему открывать элемент. В историческом руководстве первая граница начинается с 2,7 мм, а выбор ограничивается угловой зоной по направлению жеста. Настройка порогов относится к профилю ввода. [Guidelines for cross-slide, стр. 394–400](https://tilsgee.github.io/DesignGuidelinesArchive/uwp8.1.pdf#page=394) · [Документация Microsoft Learn](https://learn.microsoft.com/en-us/windows/apps/develop/input/guidelines-for-cross-slide)

Список передаёт выделенные ключи панели команд. При выборе из нескольких разделов отдельная подборка показывает все отмеченные элементы и сохраняется после применения команды. В очереди каждая запись имеет собственный ключ и порядок выполнения. При добавлении в очередь одна запись каталога может появиться в нескольких позициях. Подборка и очередь получают свои правила удаления и обратной связи. [Выбор из нескольких разделов и добавление в очередь](flows.md#28-выбор-из-нескольких-разделов-и-добавление-в-очередь)

### Перетаскивание и изменение порядка

Источник переноса объявляет ключи, данные и разрешённые операции. Цель сообщает допустимую операцию и показывает позицию вставки. Перенос внутри коллекции меняет порядок существующих ключей. При переносе между коллекциями источник удаляет элемент после подтверждённого результата Move. Отмена закрывает предпросмотр и сохраняет исходный порядок. Исторические анимации Windows 8.1 показывают поднятие элемента, открытие места и возврат остальных элементов на позиции. [Drag and drop](https://learn.microsoft.com/en-us/windows/apps/develop/data/drag-and-drop) · [Drag animations, стр. 14–15](https://tilsgee.github.io/DesignGuidelinesArchive/uwp8.1.pdf#page=14)

У встроенного изменения порядка в WinUI `ListViewBase` требуются `CanReorderItems` и `AllowDrop`. При выключенном `IsSwipeEnabled` перетаскивание касанием недоступно. Встроенное изменение порядка ограничено компоновками без группировки и без `VariableSizedWrapGrid` в роли панели элементов. Для сгруппированного представления библиотека передаёт команде ключ целевой группы и соседний элемент. Та же команда вызывается из меню или клавиатурой. [ListViewBase.CanReorderItems](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.controls.listviewbase.canreorderitems?view=windows-app-sdk-1.8) · [Перетаскивание с сохранением порядка](flows.md#29-перетаскивание-и-изменение-порядка)

### Доступные действия и состояние

Настраиваемый шаблон сохраняет доступное имя и действия базового контрола. У нового составного контрола состояние и команды видны через семантический интерфейс платформы. В WinUI их предоставляет `AutomationPeer`, который сообщает об изменении свойств и структуры. Клавиатура, касание и средство доступности вызывают одну команду с одним идентификатором цели. | --- | --- | --- |
| Кнопка, ссылка | Активация команды или назначения. Доступность зависит от состояния цели. | `Invoke` |
| CheckBox, ToggleSwitch | Переключение и чтение текущего состояния. CheckBox группы может сообщать смешанный выбор. | `Toggle` |
| Список, группа вариантов | Контейнер сообщает текущий выбор, элементы принимают выбор по ключу. | `Selection`, `SelectionItem` |

Изменение выбора обновляет строку, панель команд и семантическое состояние на основе одного значения. Обновление состава коллекции сохраняет фокус по ключу и сообщает значимый итог через отдельную область статуса. ### Визуальные состояния и шаблоны WinUI

`VisualStateGroup` собирает взаимоисключающие состояния одной характеристики. Например, в `CommonStates` контрол может быть обычным, наведённым, нажатым или недоступным. Фокус, раскрытие списка и отмеченность могут сосуществовать, поэтому им нужны свои группы. Для каждого состояния шаблон задаёт свойства через `VisualState.Setters` или анимацию через `Storyboard`. При выходе из состояния его изменения снимаются. [VisualStateGroup](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.visualstategroup) · [Control templates](https://learn.microsoft.com/en-us/windows/apps/develop/platform/xaml/xaml-control-templates)

В шаблоне `VisualStateManager.VisualStateGroups` задаётся на корневом элементе `ControlTemplate`. `TemplateBinding` передаёт значения свойств контрола, например отступ или кисть рамки. `GoToState` принимает имя состояния, а `VisualTransition` описывает визуальный переход. При адаптации стандартного контрола сохраняются имена состояний, ожидаемые его реализацией. [Control templates](https://learn.microsoft.com/en-us/windows/apps/develop/platform/xaml/xaml-control-templates) · [VisualStateManager](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.visualstatemanager) · [VisualTransition](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.visualtransition)

В библиотеке шаблон получает выбор из модели, фокус из контрола и доступность из состояния команды. Вид выделения, контур фокуса, размещение и индикатор операции могут меняться независимо. Применение команды определяется подтверждённым действием, а переход к итоговому оформлению может произойти сразу или с анимацией. [Сценарий группового выбора](flows.md#39-групповая-галочка-и-визуальные-состояния)

### Экран блокировки в Phone 8 и 8.1

Пользователь выбирает поставщика фона и приложения для отображения статуса. У **quick status** есть белый значок с прозрачностью и доступный счётчик основной плитки. **Detailed status** отображает текст основной плитки. ### Контракт библиотеки для оболочки

Плитка хранит стабильный tileId, назначение, тему, набор доступных размеров и последнее показанное содержимое. Закрепление, перемещение и снятие управляются пользователем. Источник данных публикует новое представление с версией или временем актуальности. Активация разрешает назначение через обычный маршрутизатор, поэтому запуск из плитки, ссылки и уведомления использует общую проверку параметров и загрузку. Возможности системного закрепления, отправки и управления экраном блокировки проверяет адаптер хоста. В демонстрации собственный экран закреплённых ссылок может исполнять этот контракт локально.
